tmpfs Mount چیست؟

tmpfs Mount فضای ذخیره‌سازی موقتی است که خارج از لایهٔ قابل‌نوشتن Container و در حافظهٔ میزبان قرار می‌گیرد. دادهٔ آن پس از پایان عمر Container باقی نمی‌ماند.

اصل مهم

tmpfs برای ماندگاری طراحی نشده است؛ با توقف Container دادهٔ آن از بین می‌رود. 

Host Memory
└── tmpfs
      │
      │  Mount
      ▼
Container
└── /run/app

Container stops ──► Data disappears

tmpfs Mount چه زمانی کاربرد دارد؟

  • نگهداری فایل‌های موقت برنامه که نباید روی دیسک Container باقی بمانند
  • ذخیرهٔ کوتاه‌مدت Secretها، Tokenها یا اطلاعات حساس زمان اجرا
  • Cacheهای موقتی که بازسازی آن‌ها ساده است
  • فایل‌های Session، PID یا Socket موقت برنامه
  • کاهش نوشتن فایل‌های موقت در لایهٔ قابل‌نوشتن Container
کاربرد نامناسب

دیتابیس، فایل آپلودشده و هر داده‌ای که باید پس از Restart باقی بماند نباید فقط داخل tmpfs ذخیره شود.

ویژگی‌های tmpfs Mount

ویژگی رفتار
محل نگهداری حافظهٔ میزبان؛ ممکن است سیستم‌عامل بخشی از آن را به Swap منتقل کند.
ماندگاری پس از توقف Container باقی نمی‌ماند.
اشتراک‌گذاری به همان Container وابسته است و مانند Named Volume برای اشتراک عمومی مدیریت نمی‌شود.
سیستم‌عامل در Docker Engine روی Linux پشتیبانی می‌شود؛ در Docker Desktop داخل ماشین مجازی Linux قرار می‌گیرد.

اتصال tmpfs به Container

برای ساخت tmpfs Mount می‌توان از --tmpfs یا --mount type=tmpfs استفاده کرد.

روش کوتاه با --tmpfs 

docker run --rm \
  --tmpfs /run/app \
  alpine \
  sh -c "echo temporary-data > /run/app/message.txt && cat /run/app/message.txt"

روش صریح با --mount 

docker run --rm \
  --mount type=tmpfs,destination=/run/app \
  alpine \
  sh -c "echo temporary-data > /run/app/message.txt && cat /run/app/message.txt"
--tmpfs --mount
کوتاه و مناسب اجرای تعاملی ساختار صریح با type، destination و گزینه‌های نام‌گذاری‌شده
برخی Flagهای Mount مانند noexec و nosuid را می‌پذیرد. برای تعریف خواناتر اندازه و Permission مناسب است.

محدودکردن اندازه و Permission

برای جلوگیری از مصرف کنترل‌نشدهٔ حافظه، حداکثر اندازه و Permission اولیهٔ tmpfs را مشخص کنید.

اندازه و Permission با --mount 

docker run --rm \
  --mount type=tmpfs,destination=/run/app,tmpfs-size=67108864,tmpfs-mode=1770 \
  alpine \
  df -h /run/app

در این مثال حداکثر اندازه ۶۴ MiB و Permission اولیه 1770 است.

اندازه و Flagهای امنیتی با --tmpfs 

docker run --rm \
  --tmpfs /run/app:rw,noexec,nosuid,size=64m,mode=1770 \
  alpine \
  mount | grep /run/app
کنترل منابع

tmpfs-size جایگزین محدودیت کلی حافظهٔ Container نیست؛ محدودیت Memory خود Container را نیز تنظیم کنید.

آزمایش ناپایداری داده

۱. نوشتن فایل داخل tmpfs 

docker run --name tmpfs-demo \
  --tmpfs /cache \
  alpine \
  sh -c "echo hello > /cache/message.txt && cat /cache/message.txt"

۲. شروع دوبارهٔ همان Container 

docker start -a tmpfs-demo

۳. بررسی مسیر با اجرای موقت جدید 

docker run --rm \
  --tmpfs /cache \
  alpine \
  ls -la /cache
نتیجه

در اجرای جدید مسیر tmpfs خالی است و دادهٔ قبلی مانند Volume قابل بازیابی نیست.

مقایسهٔ tmpfs، Volume و Bind Mount

ویژگی tmpfs Mount Docker Volume Bind Mount
محل داده حافظهٔ میزبان فضای مدیریت‌شده توسط Docker مسیر مشخص روی میزبان
ماندگاری پس از توقف خیر بله بله، چون فایل روی میزبان است
مدیریت توسط Docker همراه تنظیمات Container بله، با docker volume خیر، مسیر را کاربر مدیریت می‌کند
کاربرد اصلی دادهٔ موقت و حساس زمان اجرا دادهٔ ماندگار برنامه کد، پیکربندی و فایل میزبان

tmpfs در Docker Compose

تعریف ساده

services:
  app:
    image: alpine
    command: sh -c "echo ready > /run/app/status && sleep infinity"
    tmpfs:
      - /run/app

تعریف با اندازه و Permission 

services:
  app:
    image: alpine
    command: sleep infinity
    tmpfs:
      - /run/app:size=64m,mode=1770

در Compose، tmpfs بخشی از تنظیمات همان Service است و در بخش top-level volumes تعریف نمی‌شود.

مشاهدهٔ تنظیمات tmpfs

tmpfs نام مستقل ندارد و با docker volume ls نمایش داده نمی‌شود؛ تنظیمات آن را با docker inspect ببینید. 

docker inspect tmpfs-demo \
  --format '{{json .HostConfig.Tmpfs}}'

برای مشاهدهٔ مصرف و ظرفیت مسیر از ابزارهای داخل Container مانند df و mount استفاده کنید. 

docker exec tmpfs-demo df -h /cache
docker exec tmpfs-demo mount | grep /cache

امنیت و بهترین روش‌ها

  • همیشه برای tmpfs اندازهٔ مشخص تعیین کنید.
  • برای مسیرهایی که نباید فایل اجرایی داشته باشند گزینهٔ noexec را فعال کنید.
  • برای جلوگیری از اثرگذاری بیت‌های setuid و setgid از nosuid استفاده کنید.
  • Permission و مالکیت مسیر را با کاربر غیر root داخل Container هماهنگ کنید.
  • برای Secretهای بسیار حساس، تنظیمات Swap و رمزنگاری میزبان را نیز بررسی کنید.
  • اطلاعاتی را که باید Audit یا بازیابی شوند فقط در tmpfs نگه ندارید.
نکتهٔ امنیتی

tmpfs از نوشتن عادی داده در لایهٔ Container جلوگیری می‌کند، اما Swap و Dumpهای حافظه نیز باید مدیریت شوند.

تمرین عملی: دادهٔ موقت و محدودشده

گام ۱: اجرای Container با tmpfs 

docker run -d \
  --name tmpfs-lab \
  --tmpfs /run/lab:rw,noexec,nosuid,size=16m,mode=1770 \
  alpine \
  sleep infinity

گام ۲: بررسی نوع و اندازهٔ Mount 

docker exec tmpfs-lab df -h /run/lab
docker exec tmpfs-lab mount | grep /run/lab

گام ۳: نوشتن و خواندن فایل موقت 

docker exec tmpfs-lab \
  sh -c "echo 'temporary secret' > /run/lab/message.txt"

docker exec tmpfs-lab cat /run/lab/message.txt

گام ۴: Restart کردن Container 

docker restart tmpfs-lab
docker exec tmpfs-lab ls -la /run/lab

گام ۵: پاک‌سازی 

docker rm -f tmpfs-lab
نتیجهٔ تمرین

فایل پیش از Restart قابل خواندن است، اما پس از Restart مسیر خالی می‌شود و ظرفیت آن به ۱۶ MiB محدود است.

سؤالات تستی tmpfs Mount

  1. دادهٔ tmpfs پس از توقف Container چه می‌شود؟

    1. در Named Volume منتقل می‌شود
    2. از بین می‌رود
    3. داخل Image ذخیره می‌شود
    4. در Dockerfile نوشته می‌شود

    پاسخ صحیح: گزینهٔ ۲ — دادهٔ tmpfs پس از توقف Container از بین می‌رود.

  2. کدام دستور یک tmpfs Mount صریح می‌سازد؟

    1. --mount type=tmpfs,destination=/run/app
    2. --mount type=volume,source=tmpfs
    3. -v tmpfs:/run/app
    4. docker volume create tmpfs

    پاسخ صحیح: گزینهٔ ۱ — type=tmpfs نوع Mount را مشخص می‌کند.

  3. چرا باید برای tmpfs محدودیت اندازه تعیین کرد؟

    1. برای افزایش حجم Image
    2. برای جلوگیری از مصرف کنترل‌نشدهٔ حافظه
    3. برای ساخت Dockerfile
    4. برای عمومی‌کردن پورت

    پاسخ صحیح: گزینهٔ ۲ — محدودیت اندازه مصرف حافظه را کنترل می‌کند.

  4. کدام داده برای tmpfs مناسب نیست؟

    1. فایل PID موقت
    2. Cache قابل‌بازسازی
    3. دادهٔ اصلی و ماندگار دیتابیس
    4. Token کوتاه‌مدت زمان اجرا

    پاسخ صحیح: گزینهٔ ۳ — دادهٔ اصلی دیتابیس به فضای ماندگار نیاز دارد.

  5. گزینهٔ noexec چه کاری انجام می‌دهد؟

    1. اجرای مستقیم فایل از مسیر tmpfs را محدود می‌کند
    2. داده را ماندگار می‌کند
    3. اندازه را نامحدود می‌کند
    4. tmpfs را به Bind Mount تبدیل می‌کند

    پاسخ صحیح: گزینهٔ ۱ — noexec اجرای مستقیم فایل‌ها را محدود می‌کند.
