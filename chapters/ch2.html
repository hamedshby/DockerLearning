Docker Image چیست؟

Docker Image یک قالب فقط‌خواندنی (Read-Only) است که تمام اجزای موردنیاز برای اجرای یک برنامه را در خود نگهداری می‌کند.

اگر Container را یک برنامه در حال اجرا بدانیم، Docker Image همان الگوی ساخت آن برنامه است.

نکته

Docker Image همیشه Read-Only است و تغییرات در زمان اجرای Container داخل یک لایه‌ی قابل نوشتن ذخیره می‌شوند.

تفاوت Docker Image و Docker Container

یکی از رایج‌ترین اشتباهات افراد تازه‌کار، یکسان دانستن Image و Container است.

Docker Image

Image یک قالب ثابت و فقط‌خواندنی برای ساخت Container است.

Docker Container

Container نمونه‌ای در حال اجرا از یک Docker Image است.

ویژگی‌های Docker Image

Docker Image ویژگی‌های مهمی دارد که باعث محبوبیت Docker شده‌اند.

۱. Read-Only

Image همیشه ثابت و فقط‌خواندنی است.

۲. Portable

Image روی هر سیستم دارای Docker Engine قابل اجرا است.

۳. Versioned

هر Image دارای Version یا Tag مشخصی است.

۴. Layered

Docker Image از چندین Layer تشکیل شده است.

۵. Reusable

یک Image بارها قابل استفاده است.

ویژگی توضیح
Read-Only غیرقابل تغییر
Portable قابل حمل
Versioned دارای نسخه
Layered چندلایه
Reusable قابل استفاده مجدد
جمع‌بندی

Docker Image مهم‌ترین مفهوم Docker است و تقریباً تمام بخش‌های بعدی Docker بر پایه آن ساخته شده‌اند.

ساختار داخلی Docker Image (Layers)

یکی از مهم‌ترین ویژگی‌های Docker Image، ساختار چندلایه (Layered Architecture) آن است.

هر دستور در Dockerfile معمولاً یک Layer جدید ایجاد می‌کند. 

Docker Image

┌─────────────────────────────┐
│ Layer 5 : Application Files │
├─────────────────────────────┤
│ Layer 4 : Published Output  │
├─────────────────────────────┤
│ Layer 3 : NuGet Packages    │
├─────────────────────────────┤
│ Layer 2 : .NET Runtime      │
├─────────────────────────────┤
│ Layer 1 : Ubuntu / Alpine   │
└─────────────────────────────┘
نکته

Layerهای Image همیشه Read-Only هستند.

Docker Build Cache

Docker از مکانیزمی به نام Build Cache استفاده می‌کند.

مثال

COPY *.csproj .

RUN dotnet restore

COPY . .

RUN dotnet publish -c Release

Best Practice

در Production از Version مشخص استفاده کنید.

دانلود و ساخت Image

دانلود Image 

docker pull nginx
دانلود نسخه مشخص 
docker pull redis:7
دانلود Image دات‌نت 
docker pull mcr.microsoft.com/dotnet/sdk:9.0

ساخت Image 

docker build -t shop-api:v1 .

گزینه -t نام Image را مشخص می‌کند.

نمونه خروجی 
Successfully built

Successfully tagged shop-api:v1
جمع‌بندی

در این فصل مهم‌ترین مفاهیم مربوط به Docker Image را یاد گرفتید.

مدیریت Tagهای Docker Image

یک Docker Image می‌تواند چندین Tag داشته باشد.

ایجاد Tag جدید 

docker tag shop-api:v1 shop-api:latest

این دستور فقط یک Tag جدید ایجاد می‌کند.

مشاهده نتیجه 

docker images
REPOSITORY     TAG

shop-api       latest

shop-api       v1
نکته

هر دو Tag به یک Image ID اشاره می‌کنند.

ذخیره و بازیابی Docker Image

برای انتقال Image بدون Registry از save و load استفاده می‌شود.

خروجی

Load

docker load -i shop-api.tar

حذف Docker Image

حذف یک Image

docker rmi nginx
یا 
docker image rm nginx

حذف با استفاده از Image ID

docker rmi a8758716dbca

حذف اجباری

docker rmi -f nginx
هشدار

اگر Container در حال استفاده از Image باشد، Docker اجازه حذف Image را نمی‌دهد مگر اینکه از گزینه -f استفاده کنید.

پاکسازی Imageهای بدون استفاده

برای حذف Imageهایی که دیگر استفاده نمی‌شوند از دستور زیر استفاده کنید. 

docker image prune
حذف همه Imageهای بدون استفاده 
docker image prune -a
نکته

اجرای این دستور باعث آزاد شدن فضای دیسک می‌شود.

Best Practices

  • از Tagهای مشخص مانند 1.0.0 یا v1 استفاده کنید.
  • از latest در Production استفاده نکنید.
  • Imageها را تا حد امکان کوچک نگه دارید.
  • از Multi-stage Build استفاده کنید.
  • فقط فایل‌های موردنیاز را Copy کنید.
  • از Imageهای رسمی استفاده کنید.
  • به‌طور منظم Imageهای بلااستفاده را حذف کنید.

Dangling Image چیست؟

گاهی هنگام Build مجدد پروژه، Docker Imageهایی ایجاد می‌کند که دیگر هیچ Tagای ندارند. 

<none>:<none>
به این Imageها Dangling Images گفته می‌شود. مشاهده آن‌ها 
docker images -f dangling=true
حذف آن‌ها 
docker image prune

پاکسازی Imageها

حذف تمام Imageهای بلااستفاده 
docker image prune -a
حذف همه Cacheهای Build 
docker builder prune
حذف کامل Cache 
docker builder prune -a
هشدار

اجرای این دستورات ممکن است باعث شود Build بعدی زمان بیشتری طول بکشد زیرا Cache حذف خواهد شد.

Best Practices

  • از Imageهای رسمی (Official Images) استفاده کنید.
  • همیشه Version مشخص بنویسید.
  • از Tag latest در Production استفاده نکنید.
  • Imageها را کوچک نگه دارید.
  • از Multi-stage Build استفاده کنید.
  • فایل‌های غیرضروری را Copy نکنید.
  • به صورت دوره‌ای Imageهای بلااستفاده را حذف کنید.
  • Dockerfile را به گونه‌ای بنویسید که Build Cache بیشترین استفاده را داشته باشد.

سؤالات تستی فصل دوم

با این سؤالات، مفاهیم اصلی Docker Image را مرور کنید.

  1. Docker Image کدام است؟

    1. یک نمونهٔ در حال اجرای برنامه
    2. یک الگوی فقط‌خواندنی برای ساخت Container
    3. یک شبکهٔ مجازی
    4. یک فضای ذخیره‌سازی دائمی

    پاسخ صحیح: گزینهٔ ۲ — Image یک الگوی فقط‌خواندنی شامل برنامه، Runtime و وابستگی‌هاست.

  2. برای دریافت یک Image از Registry از کدام دستور استفاده می‌شود؟

    1. docker push
    2. docker pull
    3. docker save
    4. docker inspect

    پاسخ صحیح: گزینهٔ ۲ — دستور docker pull ایمیج را از Registry دریافت می‌کند.

  3. مزیت اصلی معماری لایه‌ای Docker Image چیست؟

    1. افزایش حجم Image
    2. حذف نیاز به Registry
    3. استفادهٔ مجدد از لایه‌ها و سریع‌تر شدن Build و انتقال
    4. اجرای هم‌زمان چند سیستم‌عامل

    پاسخ صحیح: گزینهٔ ۳ — لایه‌های مشترک Cache و دوباره استفاده می‌شوند.

  4. در نام my-api:2.1 بخش 2.1 چه نام دارد؟

    1. Repository
    2. Layer
    3. Tag
    4. Image ID

    پاسخ صحیح: گزینهٔ ۳ — بخش بعد از علامت دونقطه، Tag ایمیج است.

  5. کدام دستور جزئیات کامل یک Docker Image را نمایش می‌دهد؟

    1. docker image inspect
    2. docker image rm
    3. docker image prune
    4. docker run

    پاسخ صحیح: گزینهٔ ۱ — docker image inspect اطلاعاتی مانند ID، لایه‌ها و تنظیمات Image را نمایش می‌دهد.

  6. برای انتقال آفلاین یک Image ابتدا از کدام دستور استفاده می‌کنیم؟

    1. docker export
    2. docker commit
    3. docker save
    4. docker logs

    پاسخ صحیح: گزینهٔ ۳ — docker save ایمیج را در فایل tar ذخیره و docker load آن را بازیابی می‌کند.

  7. Dangling Image به چه ایمیجی گفته می‌شود؟

    1. ایمیجی که در حال دانلود است
    2. ایمیجی که Tag ندارد و معمولاً دیگر استفاده نمی‌شود
    3. ایمیجی که داخل Container اجرا شده است
    4. ایمیجی که در Registry خصوصی قرار دارد

    پاسخ صحیح: گزینهٔ ۲ — Dangling Image معمولاً Tag ندارد و با docker image prune قابل پاک‌سازی است.
