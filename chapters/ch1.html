فصل ۱: داکر چیست؟

داکر (Docker) یک پلتفرم متن‌باز برای توسعه، بسته‌بندی (Package) و اجرای برنامه‌ها درون Containerهای سبک و ایزوله است.

چرا داکر به وجود آمد؟

پیش از داکر، توسعه‌دهندگان با مشکل معروف «روی سیستم من درست کار می‌کند!» دست و پنجه نرم می‌کردند.

مشکلات پیش از داکر

  • ناسازگاری محیط توسعه، تست و Production
  • زمان‌بر بودن Setup محیط برای اعضای جدید تیم
  • مصرف بالای منابع توسط Virtual Machineها
  • پیچیدگی در استقرار چند سرویس با نسخه‌های مختلف از یک زبان یا فریمورک
  • دشواری Scale کردن برنامه‌ها به‌صورت مستقل از هم

راه‌حل داکر

داکر با معرفی مفهوم Container، برنامه و تمام وابستگی‌های آن را در یک واحد بسته‌بندی می‌کند.

نکته

داکر خودش تکنولوژی Container را اختراع نکرد؛ مفاهیمی مثل Linux Namespaces و cgroups از قبل وجود داشتند.

فصل ۲: Container در مقابل Virtual Machine

یکی از رایج‌ترین سوالاتی که برای تازه‌واردان به داکر پیش می‌آید این است: «Container با Virtual Machine چه فرقی دارد؟»

معماری Virtual Machine

یک VM از طریق Hypervisor روی سخت‌افزار فیزیکی اجرا می‌شود و هر VM شامل یک سیستم‌عامل کامل مجزا است.

معماری Container

Containerها به جای مجازی‌سازی سخت‌افزار، از Kernel سیستم‌عامل میزبان به‌صورت مشترک استفاده می‌کنند.

ویژگی Virtual Machine Container
سیستم‌عامل هر VM یک Guest OS کامل دارد Kernel مشترک با Host
حجم چند گیگابایت چند مگابایت
زمان راه‌اندازی دقیقه‌ها میلی‌ثانیه تا ثانیه
ایزوله‌سازی ایزوله‌سازی کامل در سطح سخت‌افزار ایزوله‌سازی در سطح Process
تراکم روی هر میزبان محدود (چند ده VM) بالا (چند صد تا چند هزار Container)
جمع‌بندی

VM مناسب زمانی است که به ایزوله‌سازی کامل سیستم‌عامل نیاز دارید. Container برای Deploy سریع و سبک برنامه‌ها بهتر است.

فصل ۳: معماری داکر

داکر از معماری Client-Server استفاده می‌کند. اجزای اصلی این معماری عبارتند از:

۱. Docker Client

ابزار خط فرمان (CLI) که با آن دستوراتی مثل docker run یا docker build را اجرا می‌کنید.

۲. Docker Daemon (dockerd)

فرآیند پس‌زمینه‌ای که مسئولیت ساخت، اجرا و مدیریت Containerها، Imageها، Networkها و Volumeها را بر عهده دارد.

۳. Docker Image

یک Template فقط‌خواندنی که شامل کد برنامه، Runtime، کتابخانه‌ها و تنظیمات لازم برای اجرای آن است.

۴. Docker Container

یک نمونه (Instance) در حال اجرا از یک Image. Container شامل یک لایه‌ی قابل نوشتن است.

۵. Docker Registry

محلی برای ذخیره و توزیع Imageها. Docker Hub معروف‌ترین Registry عمومی است.

جریان کار ساده:

Docker Client  --(docker run nginx)-->  Docker Daemon

                                             v
                                  آیا Image نگین موجود است؟
                                    /                \
                                  بله                 خیر
                                   |                   |
                                   v                   v
                        اجرای Container         Pull از Registry
                                                        |
                                                        v

فصل ۴: Docker Desktop، Docker Hub و Workflow

Docker Desktop

Docker Desktop یک اپلیکیشن گرافیکی برای Windows و macOS است که شامل Docker Engine، CLI، Compose و رابط کاربری می‌باشد.

Docker Hub

Docker Hub بزرگ‌ترین Registry عمومی برای Imageهای داکر است.

Workflow معمول کار با داکر

  1. نوشتن Dockerfile برای برنامه
  2. ساخت Image با دستور docker build
  3. اجرای Container از روی Image با docker run
  4. تست و اشکال‌زدایی Container به‌صورت لوکال
  5. Push کردن Image به یک Registry
  6. Pull و اجرای Image روی سرور Production
مرتبط با پروژه

در این کتاب، همین Workflow را برای هر یک از سرویس‌های پروژه E-Commerce Microservices طی خواهیم کرد.

Lab ۱: نصب داکر و اجرای اولین Container

گام ۱: نصب Docker Desktop

از سایت رسمی داکر نسخه‌ی مناسب سیستم‌عامل خود را دانلود و نصب کنید.

گام ۲: بررسی نصب

در ترمینال یا PowerShell دستور زیر را اجرا کنید: 

docker --version
docker info

گام ۳: اجرای Hello World

docker run hello-world

اگر پیام موفقیت‌آمیز مشاهده کردید، یعنی داکر شما به درستی نصب شده است.

گام ۴: اجرای یک Web Server ساده (Nginx)

docker run -d -p 8080:80 --name my-nginx nginx
  • -d : اجرا در پس‌زمینه (Detached Mode)
  • -p 8080:80 : نگاشت پورت ۸۰ داخل Container به پورت ۸۰۸۰ سیستم شما
  • --name my-nginx : نام‌گذاری Container برای دسترسی آسان‌تر

حالا آدرس http://localhost:8080 را در مرورگر باز کنید تا صفحه‌ی خوش‌آمدگویی Nginx را ببینید.

گام ۵: مشاهده Containerهای در حال اجرا

docker ps

گام ۶: توقف و حذف Container

docker stop my-nginx
docker rm my-nginx
