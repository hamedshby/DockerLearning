دستور CMD

دستور CMD فرمان پیش‌فرضی را مشخص می‌کند که هنگام اجرای Container اجرا خواهد شد.

نکته

CMD هنگام اجرای docker build اجرا نمی‌شود؛ بلکه در زمان docker run اجرا خواهد شد.

زمان اجرای CMD 

Dockerfile

     │

docker build

     │

Docker Image

     │

docker run

     │

CMD

     ▼

Application Starts

CMD نقطه شروع اجرای برنامه داخل Container است.

Syntax

Exec Form (پیشنهاد Docker)


CMD ["dotnet","Shop.Api.dll"]

Shell Form


CMD dotnet Shop.Api.dll
Best Practice

Docker پیشنهاد می‌کند همیشه از Exec Form استفاده کنید.

چرا Exec Form؟

Exec Form پردازش برنامه را مستقیماً اجرا می‌کند و سیگنال‌های سیستم‌عامل (مانند SIGTERM) را به درستی دریافت می‌کند.

Exec Form Shell Form
✔ Performance بهتر پردازش از طریق Shell اجرا می‌شود.
✔ دریافت صحیح Signalها ممکن است Signalها را دریافت نکند.
✔ پیشنهاد Docker فقط در شرایط خاص

مثال‌ها

اجرای برنامه دات‌نت


CMD ["dotnet","Shop.Api.dll"]

اجرای Nginx


CMD ["nginx","-g","daemon off;"]

اجرای Bash


CMD ["/bin/bash"]

نمایش پیام


CMD ["echo","Hello Docker"]

فقط یک CMD

در هر Dockerfile فقط آخرین دستور CMD معتبر خواهد بود.

نمونه 

CMD ["echo","First"]

CMD ["echo","Second"]
نتیجه 

Second

دستور اول نادیده گرفته می‌شود.

Override کردن CMD

دستور CMD را می‌توان هنگام اجرای Container تغییر داد.

Dockerfile 

CMD ["dotnet","Shop.Api.dll"]
اجرای معمولی 

docker run shop-api
Override 

docker run shop-api bash
یا 

docker run ubuntu ls
در این حالت CMD اجرا نمی‌شود. بلکه دستور جدید اجرا خواهد شد.

نمونه ASP.NET Core 


FROM mcr.microsoft.com/dotnet/aspnet:9.0

WORKDIR /app

COPY publish .

CMD ["dotnet","Shop.Api.dll"]
در این مثال
  • Image ساخته می‌شود.
  • هیچ برنامه‌ای هنگام Build اجرا نمی‌شود.
  • پس از docker run برنامه ASP.NET Core اجرا می‌شود.

تفاوت RUN و CMD

RUN CMD
هنگام Build اجرا می‌شود. هنگام اجرای Container اجرا می‌شود.
Layer جدید ایجاد می‌کند. Layer ایجاد نمی‌کند.
نتیجه داخل Image ذخیره می‌شود. فقط برنامه را اجرا می‌کند.
قابل Override نیست. قابل Override است.

Best Practices

  • از Exec Form استفاده کنید.
  • فقط یک CMD در Dockerfile قرار دهید.
  • CMD را کوتاه و ساده نگه دارید.
  • اجرای برنامه اصلی را به CMD بسپارید.
اشتباهات رایج
  • استفاده از چند CMD در یک Dockerfile
  • استفاده از Shell Form بدون نیاز
  • قرار دادن دستورات نصب نرم‌افزار داخل CMD
  • اشتباه گرفتن CMD با RUN

نمونه واقعی 


FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build

WORKDIR /src

COPY *.csproj .

RUN dotnet restore

COPY . .

RUN dotnet publish -c Release -o /publish

FROM mcr.microsoft.com/dotnet/aspnet:9.0

WORKDIR /app

COPY --from=build /publish .

CMD ["dotnet","Shop.Api.dll"]

در این Dockerfile، تمام مراحل Build توسط RUN انجام می‌شود و اجرای برنامه به CMD سپرده شده است.
