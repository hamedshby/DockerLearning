دستور CMD

دستور CMD فرمان پیش‌فرضی را مشخص می‌کند که هنگام اجرای Container اجرا خواهد شد.

نکته

CMD هنگام اجرای docker build اجرا نمی‌شود؛ بلکه در زمان docker run اجرا خواهد شد.

زمان اجرای CMD 

Dockerfile

     │

docker build

     │

Docker Image

     │

docker run

     │

CMD

     ▼

Application Starts

CMD نقطه شروع اجرای برنامه داخل Container است.

Syntax

Exec Form (پیشنهاد Docker)


CMD ["dotnet","Shop.Api.dll"]

Shell Form


CMD dotnet Shop.Api.dll
Best Practice

Docker پیشنهاد می‌کند همیشه از Exec Form استفاده کنید.

چرا Exec Form؟

Exec Form پردازش برنامه را مستقیماً اجرا می‌کند و سیگنال‌های سیستم‌عامل (مانند SIGTERM) را به درستی دریافت می‌کند.

Exec Form Shell Form
✔ Performance بهتر پردازش از طریق Shell اجرا می‌شود.
✔ دریافت صحیح Signalها ممکن است Signalها را دریافت نکند.
✔ پیشنهاد Docker فقط در شرایط خاص

مثال‌ها

اجرای برنامه دات‌نت


CMD ["dotnet","Shop.Api.dll"]

اجرای Nginx


CMD ["nginx","-g","daemon off;"]

اجرای Bash


CMD ["/bin/bash"]

نمایش پیام


CMD ["echo","Hello Docker"]

فقط یک CMD

در هر Dockerfile فقط آخرین دستور CMD معتبر خواهد بود.

نمونه 

CMD ["echo","First"]

CMD ["echo","Second"]
نتیجه 

Second

دستور اول نادیده گرفته می‌شود.

Override کردن CMD

دستور CMD را می‌توان هنگام اجرای Container تغییر داد.

Dockerfile 

CMD ["dotnet","Shop.Api.dll"]
اجرای معمولی 

docker run shop-api
Override 

docker run shop-api bash
یا 

docker run ubuntu ls
در این حالت CMD اجرا نمی‌شود. بلکه دستور جدید اجرا خواهد شد.

نمونه ASP.NET Core 


FROM mcr.microsoft.com/dotnet/aspnet:9.0

WORKDIR /app

CMD ["dotnet","Shop.Api.dll"]
در این مثال
  • Image ساخته می‌شود.
  • هیچ برنامه‌ای هنگام Build اجرا نمی‌شود.
  • پس از docker run برنامه ASP.NET Core اجرا می‌شود.

تفاوت RUN و CMD

RUN CMD
هنگام Build اجرا می‌شود. هنگام اجرای Container اجرا می‌شود.
Layer جدید ایجاد می‌کند. Layer ایجاد نمی‌کند.
نتیجه داخل Image ذخیره می‌شود. فقط برنامه را اجرا می‌کند.
قابل Override نیست. قابل Override است.

Best Practices

  • از Exec Form استفاده کنید.
  • فقط یک CMD در Dockerfile قرار دهید.
  • CMD را کوتاه و ساده نگه دارید.
  • اجرای برنامه اصلی را به CMD بسپارید.
اشتباهات رایج
  • استفاده از چند CMD در یک Dockerfile
  • استفاده از Shell Form بدون نیاز
  • قرار دادن دستورات نصب نرم‌افزار داخل CMD
  • اشتباه گرفتن CMD با RUN

نمونه واقعی 


FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build

WORKDIR /src

COPY *.csproj .

RUN dotnet restore

COPY . .

RUN dotnet publish -c Release -o /publish

FROM mcr.microsoft.com/dotnet/aspnet:9.0

WORKDIR /app

COPY --from=build /publish .

CMD ["dotnet","Shop.Api.dll"]

در این Dockerfile، تمام مراحل Build توسط RUN انجام می‌شود و اجرای برنامه به CMD سپرده شده است.

سؤالات تستی دستور CMD

با این سؤالات، کاربرد و رفتار دستور CMD را مرور کنید.

  1. دستور CMD در Dockerfile چه کاری انجام می‌دهد؟

    1. فرمان پیش‌فرض زمان اجرای Container را تعیین می‌کند
    2. Base Image را انتخاب می‌کند
    3. فایل‌ها را به Image کپی می‌کند
    4. Image را در Registry ذخیره می‌کند

    پاسخ صحیح: گزینهٔ ۱ — CMD فرمان یا آرگومان پیش‌فرضی را مشخص می‌کند که هنگام شروع Container استفاده می‌شود.

  2. دستور CMD چه زمانی اجرا می‌شود؟

    1. هنگام docker build
    2. هنگام شروع Container
    3. هنگام docker pull
    4. هنگام حذف Image

    پاسخ صحیح: گزینهٔ ۲ — CMD در زمان Build اجرا نمی‌شود و مقدار آن برای زمان اجرای Container در Image ثبت می‌شود.

  3. کدام نمونه Exec Form صحیح دستور CMD است؟

    1. CMD dotnet Shop.Api.dll
    2. CMD ["dotnet", "Shop.Api.dll"]
    3. RUN ["dotnet", "Shop.Api.dll"]
    4. CMD = dotnet Shop.Api.dll

    پاسخ صحیح: گزینهٔ ۲ — Exec Form به‌صورت آرایهٔ JSON نوشته می‌شود و برنامه و آرگومان‌ها عناصر جداگانه دارند.

  4. اگر پس از نام Image در docker run یک فرمان بنویسیم چه اتفاقی می‌افتد؟

    1. فرمان CMD بازنویسی می‌شود
    2. Dockerfile حذف می‌شود
    3. یک Base Image جدید ساخته می‌شود
    4. Build دوباره اجرا می‌شود

    پاسخ صحیح: گزینهٔ ۱ — فرمان انتهای docker run جایگزین CMD پیش‌فرض Image می‌شود.

  5. اگر چند دستور CMD در یک Build Stage نوشته شود کدام‌یک استفاده می‌شود؟

    1. همهٔ آن‌ها به‌ترتیب اجرا می‌شوند
    2. اولین CMD
    3. آخرین CMD
    4. هیچ‌کدام

    پاسخ صحیح: گزینهٔ ۳ — در هر Build Stage فقط آخرین CMD مؤثر است.

  6. تفاوت اصلی CMD و ENTRYPOINT چیست؟

    1. CMD معمولاً مقدار پیش‌فرض قابل بازنویسی است؛ ENTRYPOINT برنامهٔ اصلی Container را تثبیت می‌کند
    2. CMD فقط در Windows کار می‌کند
    3. ENTRYPOINT هنگام Build اجرا می‌شود
    4. هیچ تفاوتی ندارند

    پاسخ صحیح: گزینهٔ ۱ — ENTRYPOINT معمولاً برنامهٔ اصلی را تعیین می‌کند و CMD می‌تواند آرگومان‌های پیش‌فرض آن باشد.
