دستور RUN

دستور RUN برای اجرای دستورات هنگام ساخت Docker Image استفاده می‌شود.

نکته

RUN فقط در زمان Build اجرا می‌شود، نه هنگام اجرای Container.

زمان اجرای RUN 

Dockerfile

     │

docker build

     │

RUN apt-get update

RUN apt-get install nginx

     │

Docker Image

     │

docker run

     ▼

Container

تمام دستورات RUN قبل از ساخته شدن Image اجرا می‌شوند.

Syntax

Shell Form


RUN apt-get update

Exec Form


RUN ["apt-get","update"]
نکته

در اکثر Dockerfileها از Shell Form استفاده می‌شود.

مثال‌های متداول

بروزرسانی Packageها


RUN apt-get update

نصب نرم‌افزار


RUN apt-get install -y curl

ساخت پوشه


RUN mkdir /app

ایجاد فایل


RUN touch version.txt

تغییر Permission


RUN chmod +x start.sh

Restore پروژه دات‌نت


RUN dotnet restore

Publish پروژه


RUN dotnet publish -c Release -o /publish

RUN و Build Cache

هر RUN یک Layer ایجاد می‌کند. اگر دستور تغییر نکند، Docker از Cache استفاده می‌کند.

Rebuild

Best Practices

  • چند دستور را در یک RUN ترکیب کنید.
  • پس از نصب Packageها Cache را حذف کنید.
  • از && استفاده کنید.
  • تعداد Layerها را کاهش دهید.
نمونه حرفه‌ای 

RUN apt-get update && \
    apt-get install -y curl && \
    rm -rf /var/lib/apt/lists/*
این روش باعث کاهش حجم Image می‌شود.

RUN و CMD

RUN CMD
هنگام Build اجرا می‌شود. هنگام اجرای Container اجرا می‌شود.
Layer جدید ایجاد می‌کند. Layer ایجاد نمی‌کند.
نتیجه داخل Image ذخیره می‌شود. فقط برنامه را اجرا می‌کند.

نمونه واقعی ASP.NET Core 


FROM mcr.microsoft.com/dotnet/sdk:9.0

WORKDIR /src

COPY *.csproj .

RUN dotnet restore

COPY . .

RUN dotnet publish -c Release -o /publish
در این Dockerfile
  • Restore هنگام Build انجام می‌شود.
  • Publish هنگام Build انجام می‌شود.
  • نتیجه داخل Image ذخیره می‌شود.

سؤالات تستی دستور RUN

با این سؤالات، کاربرد دستور RUN و روش‌های بهینه‌سازی آن را مرور کنید.

  1. دستور RUN چه زمانی اجرا می‌شود؟

    1. هنگام Build شدن Image
    2. فقط هنگام توقف Container
    3. هنگام Push به Registry
    4. بعد از حذف Image

    پاسخ صحیح: گزینهٔ ۱ — RUN در زمان docker build اجرا می‌شود و نتیجهٔ آن در Image ذخیره می‌شود.

  2. هر دستور RUN معمولاً چه اثری روی Docker Image دارد؟

    1. یک Container دائمی ایجاد می‌کند
    2. یک Layer جدید ایجاد می‌کند
    3. تمام Layerهای قبلی را حذف می‌کند
    4. Tag ایمیج را تغییر می‌دهد

    پاسخ صحیح: گزینهٔ ۲ — نتیجهٔ هر RUN معمولاً به‌صورت یک Layer جدید در Image ثبت می‌شود.

  3. کدام نمونه Shell Form دستور RUN است؟

    1. RUN apt-get update
    2. RUN ["apt-get", "update"]
    3. CMD ["apt-get", "update"]
    4. FROM apt-get:update

    پاسخ صحیح: گزینهٔ ۱ — نوشتن فرمان به‌صورت متن بعد از RUN، Shell Form است.

  4. چرا دستورهای مرتبط apt-get بهتر است در یک RUN ترکیب شوند؟

    1. برای کاهش Layerهای اضافی و جلوگیری از Cache نامعتبر
    2. برای اجرای دستورها هنگام شروع Container
    3. برای تغییر Base Image
    4. برای ساخت Volume

    پاسخ صحیح: گزینهٔ ۱ — ترکیب update، install و پاک‌سازی در یک RUN، Layer و دادهٔ اضافی را کاهش می‌دهد.

  5. برای مشاهدهٔ Layerهای ایجادشده توسط RUN از کدام دستور استفاده می‌شود؟

    1. docker ps
    2. docker logs
    3. docker history image-name
    4. docker volume ls

    پاسخ صحیح: گزینهٔ ۳ — docker history تاریخچه و Layerهای Image را نمایش می‌دهد.

  6. تفاوت اصلی RUN و CMD چیست؟

    1. RUN هنگام Build اجرا می‌شود؛ CMD فرمان پیش‌فرض زمان اجرای Container را تعیین می‌کند
    2. RUN فقط برای Windows و CMD فقط برای Linux است
    3. هر دو دقیقاً یک کار انجام می‌دهند
    4. CMD هنگام Build اجرا می‌شود و RUN هنگام Push

    پاسخ صحیح: گزینهٔ ۱ — RUN بخشی از فرایند ساخت Image است، اما CMD هنگام اجرای Container استفاده می‌شود.
