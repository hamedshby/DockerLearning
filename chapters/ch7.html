Docker Volume چیست؟

فایل‌هایی که یک Container داخل لایهٔ قابل‌نوشتن خود ایجاد می‌کند، به عمر همان Container وابسته‌اند. Docker Volume فضای ذخیره‌سازی مستقلی است که Docker آن را مدیریت می‌کند و داده‌ها را خارج از Container نگه می‌دارد.

اصل مهم

Container باید قابل حذف و جایگزینی باشد، اما داده‌های مهم آن باید مستقل و ماندگار باقی بمانند. 

Container
    │
    │  Mount
    ▼
Docker Volume
    │
    └── Data survives Container removal

چرا به Docker Volume نیاز داریم؟

  • ماندگاری اطلاعات پس از حذف یا ساخت مجدد Container
  • جداکردن چرخهٔ عمر داده از چرخهٔ عمر Container
  • اشتراک‌گذاری کنترل‌شدهٔ داده بین چند Container
  • مدیریت ساده‌تر Backup و Restore
  • عملکرد بهتر نسبت به نوشتن داده در لایهٔ داخلی Container
کاربرد رایج

دیتابیس‌هایی مانند SQL Server، PostgreSQL و MySQL باید اطلاعات خود را داخل Volume ذخیره کنند.

Named Volume و Anonymous Volume

نوع نمونه ویژگی
Named Volume db-data:/var/lib/data نام مشخص دارد و مدیریت و استفادهٔ مجدد از آن ساده‌تر است.
Anonymous Volume /var/lib/data Docker یک نام تصادفی برای آن می‌سازد و مدیریت آن دشوارتر است.
Best Practice

برای داده‌های مهم و قابل‌مدیریت، از Named Volume استفاده کنید.

ساخت و مشاهدهٔ Volumeها

ساخت Volume

docker volume create app-data

مشاهدهٔ Volumeها

docker volume ls

مشاهدهٔ جزئیات Volume

docker volume inspect app-data

خروجی inspect شامل نام Volume، Driver، محل نگهداری و Labelهای آن است. مسیر فیزیکی Volume را Docker مدیریت می‌کند.

اتصال Volume به Container

برای اتصال Volume می‌توان از گزینهٔ کوتاه -v یا گزینهٔ خواناتر --mount استفاده کرد.

روش کوتاه با -v

docker run -d \
  --name web \
  -v app-data:/usr/share/nginx/html \
  nginx

بخش سمت چپ نام Volume و بخش سمت راست مسیر داخل Container است.

روش خواناتر با --mount 

docker run -d \
  --name web \
  --mount type=volume,source=app-data,target=/usr/share/nginx/html \
  nginx
-v --mount
کوتاه و مناسب استفادهٔ روزمره خواناتر، صریح‌تر و مناسب اسکریپت‌ها و محیط Production

آزمایش ماندگاری داده

۱. ساخت Volume

docker volume create demo-data

۲. نوشتن اطلاعات داخل Volume 

docker run --rm \
  -v demo-data:/data \
  alpine \
  sh -c "echo 'Hello from Docker Volume' > /data/message.txt"

۳. خواندن اطلاعات با یک Container جدید 

docker run --rm \
  -v demo-data:/data \
  alpine \
  cat /data/message.txt
نتیجه

Container اول حذف می‌شود، اما Container دوم همچنان فایل ذخیره‌شده در Volume را می‌خواند.

استفاده از Volume برای SQL Server 

docker volume create sql-data

docker run -d \
  --name sql-server \
  -e "ACCEPT_EULA=Y" \
  -e "MSSQL_SA_PASSWORD=Your_Strong_Password123!" \
  -p 1433:1433 \
  -v sql-data:/var/opt/mssql \
  mcr.microsoft.com/mssql/server:2022-latest

SQL Server داده‌های خود را در مسیر /var/opt/mssql نگه می‌دارد. با اتصال sql-data به این مسیر، حذف و ساخت مجدد Container باعث حذف دیتابیس‌ها نمی‌شود.

نکتهٔ امنیتی

رمز عبور واقعی را مستقیماً داخل Dockerfile یا Git ذخیره نکنید.

حذف و پاک‌سازی Volumeها

حذف یک Volume

docker volume rm app-data

حذف Volumeهای بدون استفاده 

docker volume prune
هشدار

حذف Volume معمولاً به معنی حذف دائمی داده‌های آن است. پیش از پاک‌سازی از داده‌های مهم Backup تهیه کنید.

بهترین روش‌های استفاده از Volume

  • برای داده‌های مهم از Named Volume با نام واضح استفاده کنید.
  • قبل از حذف Volume از اطلاعات مهم Backup بگیرید.
  • رمز عبور و اطلاعات حساس را داخل Volume عمومی یا Image قرار ندهید.
  • Permission مسیر مقصد را با کاربر داخل Container هماهنگ کنید.
  • Volumeهای بدون مالک و بدون استفاده را دوره‌ای بررسی کنید.

تمرین عملی: ماندگاری داده با Volume

گام ۱: ساخت Volume

docker volume create nginx-data

گام ۲: ایجاد فایل HTML 

docker run --rm \
  -v nginx-data:/data \
  alpine \
  sh -c "echo '<h1>Docker Volume Works</h1>' > /data/index.html"

گام ۳: اجرای Nginx

docker run -d \
  --name volume-web \
  -p 8080:80 \
  -v nginx-data:/usr/share/nginx/html:ro \
  nginx

گام ۴: مشاهده در مرورگر 

http://localhost:8080

گام ۵: ساخت مجدد Container 

docker rm -f volume-web

docker run -d \
  --name volume-web-new \
  -p 8080:80 \
  -v nginx-data:/usr/share/nginx/html:ro \
  nginx
نتیجهٔ تمرین

Container اول حذف شد، اما صفحهٔ HTML داخل nginx-data باقی ماند و Container جدید همان داده را نمایش داد.

سؤالات تستی Docker Volume

  1. هدف اصلی Docker Volume چیست؟

    1. افزایش سرعت اینترنت
    2. نگهداری داده مستقل از عمر Container
    3. ساخت Dockerfile
    4. تغییر Base Image

    پاسخ صحیح: گزینهٔ ۲ — Volume داده را خارج از لایهٔ قابل‌نوشتن Container نگه می‌دارد.

  2. کدام دستور یک Named Volume می‌سازد؟

    1. docker volume create app-data
    2. docker create volume app-data
    3. docker run volume app-data
    4. docker image create app-data

    پاسخ صحیح: گزینهٔ ۱ — docker volume create برای ساخت Volume استفاده می‌شود.

  3. در -v db-data:/var/lib/data بخش سمت چپ چیست؟

    1. مسیر داخل Container
    2. نام Volume
    3. نام Image
    4. شمارهٔ پورت

    پاسخ صحیح: گزینهٔ ۲ — db-data نام Volume و مسیر بعدی محل اتصال داخل Container است.

  4. پس از حذف Container متصل به Named Volume چه اتفاقی برای داده می‌افتد؟

    1. داده همیشه همراه Container حذف می‌شود
    2. Volume و داده مستقل باقی می‌مانند
    3. داده به Dockerfile منتقل می‌شود
    4. Image به‌صورت خودکار حذف می‌شود

    پاسخ صحیح: گزینهٔ ۲ — Named Volume چرخهٔ عمر مستقلی از Container دارد.

  5. کدام دستور Volumeهای بدون استفاده را پاک می‌کند؟

    1. docker volume prune
    2. docker image prune
    3. docker container prune
    4. docker volume stop

    پاسخ صحیح: گزینهٔ ۱ — docker volume prune Volumeهای بدون استفاده را حذف می‌کند.
