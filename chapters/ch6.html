شبکه‌بندی Docker چیست؟

Docker Networking ارتباط میان Containerها، میزبان و شبکه‌های خارجی را فراهم می‌کند.

اصل مهم

برای ارتباط داخلی پایدار، از نام سرویس استفاده کنید نه IP ثابت. 

Internet / Host
      │
      │  published port 8080:80
      ▼
┌──────────── Docker Host ────────────┐
│  user-defined bridge: app-net       │
│                                     │
│  web:80 ─────── DNS ─────── api:5000│
│                         │           │
│                         └── db:1433 │
└─────────────────────────────────────┘

مسیرهای اصلی ترافیک

مسیر روش دسترسی نمونه
Container به Container نام سرویس و پورت داخلی http://api:5000
میزبان به Container Port Publishing http://localhost:8080
Container به اینترنت مسیریابی از طریق میزبان https://example.com

Driverهای شبکه در Docker

Network Driver نحوهٔ ساخت شبکه و عبور ترافیک را تعیین می‌کند.

Driver کاربرد نکته
bridge ارتباط روی یک میزبان انتخاب معمول تک‌میزبان
host اشتراک شبکهٔ میزبان ایزوله‌سازی کمتر و وابسته به پلتفرم
none بدون اتصال خارجی ایزوله‌ترین حالت شبکه
overlay شبکهٔ چندمیزبان Swarm مناسب Swarm
macvlan دستگاه مستقل در LAN پیکربندی پیشرفته
ipvlan اتصال مستقیم‌تر به شبکه کاربرد پیشرفته
انتخاب پیشنهادی

برای برنامهٔ تک‌میزبان از یک User-defined Bridge شروع کنید.

Default Bridge و User-defined Bridge

برای برنامه‌های چند-Container، شبکهٔ Bridge سفارشی انتخاب بهتری است.

ویژگی Default bridge User-defined bridge
DNS نام Container محدود داخلی و خودکار
ایزوله‌سازی شبکهٔ مشترک عمومی شبکهٔ مجزا برای هر برنامه
اتصال در زمان اجرا انعطاف کمتر انعطاف‌پذیر

ساخت و مدیریت شبکه

مشاهدهٔ شبکه‌ها

docker network ls

ساخت User-defined Bridge

docker network create --driver bridge app-net

مشاهدهٔ جزئیات شبکه

docker network inspect app-net

Inspect اطلاعات Driver، Subnet، Gateway و Containerهای متصل را نشان می‌دهد. 

docker network inspect app-net \
  --format '{{json .Containers}}'

حذف شبکه

docker network rm app-net
شرط حذف

پیش از حذف شبکه، Containerهای متصل را جدا کنید.

DNS داخلی و کشف سرویس

Docker Embedded DNS نام Container را به IP فعلی آن Resolve می‌کند. 

docker network create app-net

docker run -d --name api --network app-net nginx

docker run --rm --network app-net curlimages/curl \
  http://api

کشف نام فقط داخل شبکهٔ مشترک انجام می‌شود.

پورت داخلی، EXPOSE و Port Publishing

برای دسترسی از میزبان باید پورت را با -p منتشر کنید. 

docker run -d \
  --name web \
  --network app-net \
  -p 8080:80 \
  nginx
مقدار معنا
8080 پورت میزبان
80 پورت داخل Container
127.0.0.1:8080:80 انتشار فقط روی localhost
حداقل سطح دسترسی

فقط پورت‌هایی را Publish کنید که واقعاً باید از میزبان قابل دسترسی باشند.

اتصال Container به چند شبکه

اتصال چندشبکه‌ای امکان جداسازی لایه‌های برنامه را فراهم می‌کند. 

docker network create frontend
docker network create backend

docker run -d --name api --network frontend nginx
docker network connect backend api

docker network disconnect frontend api

امنیت شبکهٔ Docker

  • برای هر Trust Zone شبکهٔ جدا بسازید.
  • فقط پورت‌های ضروری را Publish کنید.
  • دیتابیس را عمومی نکنید.
  • برای ترافیک حساس از TLS و احراز هویت استفاده کنید.
  • Firewall میزبان را نیز بررسی کنید.

عیب‌یابی شبکه‌های Docker

  1. وضعیت Container و Port Mapping را ببینید.
  2. عضویت در شبکه را بررسی کنید.
  3. DNS داخلی را آزمایش کنید.
  4. آدرس Listen برنامه را بررسی کنید.
  5. ترتیب پورت‌ها را بررسی کنید.
docker ps
docker port web
docker network inspect app-net
docker inspect web --format '{{json .NetworkSettings.Networks}}'

docker run --rm --network app-net busybox nslookup web
docker run --rm --network app-net busybox wget -qO- http://web
خطای رایج

داخل Container، localhost همان Container جاری است.

تمرین عملی: ارتباط دو Container روی شبکهٔ سفارشی

گام ۱: ساخت شبکه

docker network create lab-net

گام ۲: اجرای Web Server

docker run -d \
  --name lab-web \
  --network lab-net \
  -p 8080:80 \
  nginx

گام ۳: دسترسی با نام Container 

docker run --rm \
  --network lab-net \
  curlimages/curl \
  http://lab-web

گام ۴: بررسی DNS داخلی

docker run --rm --network lab-net busybox nslookup lab-web

گام ۵: دسترسی از میزبان

curl http://localhost:8080

گام ۶: پاک‌سازی

docker rm -f lab-web
docker network rm lab-net
نتیجهٔ تمرین

ارتباط داخلی با نام Container و ارتباط میزبان با پورت 8080 انجام شد.

سؤالات تستی Docker Networking

  1. روش پایدار ارتباط داخلی چیست؟

    • IP دستی
    • نام سرویس
    • پورت تصادفی
    • شناسهٔ Image

    پاسخ صحیح: گزینهٔ ۲

  2. عدد 8080 چیست؟

    • پورت میزبان
    • پورت Container
    • Subnet
    • شناسهٔ شبکه

    پاسخ صحیح: گزینهٔ ۱

  3. Driver معمول تک‌میزبان چیست؟

    • overlay
    • bridge
    • none
    • macvlan

    پاسخ صحیح: گزینهٔ ۲

  4. localhost داخل Container چیست؟

    • میزبان Docker
    • Container دیگر
    • همان Container جاری
    • Docker Hub

    پاسخ صحیح: گزینهٔ ۳

  5. دستور اتصال به شبکه چیست؟

    • docker network connect backend api
    • docker network rm backend
    • docker image connect api
    • docker port disconnect api

    پاسخ صحیح: گزینهٔ ۱
