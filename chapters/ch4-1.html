دستور FROM

دستور FROM نقطه شروع هر Dockerfile است و Image پایه (Base Image) را مشخص می‌کند.

نکته

Docker بدون وجود FROM نمی‌تواند Image را Build کند.

Syntax 


FROM <image>

FROM <image>:<tag>

FROM <registry>/<repository>:<tag>
نمونه‌ها 

FROM nginx

FROM ubuntu:24.04

FROM redis:7

FROM mcr.microsoft.com/dotnet/sdk:9.0

Base Image چیست؟

Base Image اولین Layer از Docker Image شماست. 

Docker Image

┌─────────────────────┐
│ Application         │
├─────────────────────┤
│ .NET Runtime        │
├─────────────────────┤
│ Base Image (Ubuntu) │
└─────────────────────┘

تمام Layerهای بعدی روی Base Image ساخته می‌شوند.

Imageهای پایه پرکاربرد

Image کاربرد
ubuntu سیستم‌عامل عمومی لینوکس
alpine Image بسیار سبک
nginx وب سرور
redis Redis Server
postgres PostgreSQL
mcr.microsoft.com/dotnet/sdk Build پروژه‌های .NET
mcr.microsoft.com/dotnet/aspnet اجرای برنامه‌های ASP.NET Core

مثال 


FROM mcr.microsoft.com/dotnet/sdk:9.0
توضیح
  • Image رسمی مایکروسافت
  • دارای .NET SDK
  • مناسب Build پروژه
Best Practice
  • همیشه Version مشخص بنویسید.
  • از Imageهای رسمی استفاده کنید.
  • در Production از latest استفاده نکنید.
اشتباهات رایج
  • استفاده از latest
  • استفاده از Imageهای ناشناس
  • انتخاب Imageهای بسیار بزرگ

دستور WORKDIR

WORKDIR مسیر کاری Docker را مشخص می‌کند.

بعد از اجرای WORKDIR تمام دستورات COPY ، RUN ، CMD و سایر دستورات در همان مسیر اجرا خواهند شد.

Syntax 


WORKDIR /app
یا 

WORKDIR /src

مثال 


FROM mcr.microsoft.com/dotnet/sdk:9.0

WORKDIR /app

COPY . .

RUN dotnet restore
در این مثال تمام فایل‌ها داخل پوشه /app کپی خواهند شد. 
Container

/

├── app  ◄── Current Working Directory

│

├── bin

├── usr

├── etc

└── var

مسیرهای نسبی 


WORKDIR /app

WORKDIR src
نتیجه 

/app/src
Docker مسیر دوم را به مسیر اول اضافه می‌کند.

چند WORKDIR 


WORKDIR /app

WORKDIR api

WORKDIR publish
نتیجه 

/app/api/publish

تفاوت WORKDIR و RUN cd

WORKDIR RUN cd
برای تمام دستورات بعدی اعمال می‌شود. فقط همان RUN را تغییر می‌دهد.
پیشنهاد Docker استفاده نشود.
نمونه اشتباه 

RUN cd /app

RUN dotnet restore
در دستور دوم دوباره مسیر به حالت قبل برمی‌گردد. نمونه صحیح 

WORKDIR /app

RUN dotnet restore
Best Practice
  • همیشه از WORKDIR استفاده کنید.
  • از RUN cd استفاده نکنید.
  • مسیرهای کوتاه و خوانا انتخاب کنید.
  • معمولاً از مسیر /app استفاده می‌شود.

در این آزمایش یاد گرفتید چگونه با استفاده از دستور FROM یک Base Image انتخاب کنید و با دستور WORKDIR مسیر کاری پروژه را مشخص نمایید. تقریباً تمام Dockerfileهای حرفه‌ای با این دو دستور آغاز می‌شوند و پایه‌ی سایر دستورات Dockerfile را تشکیل می‌دهند.

سؤالات تستی FROM و WORKDIR

با این سؤالات، کاربرد دو دستور پایه‌ای FROM و WORKDIR را مرور کنید.

  1. دستور FROM در Dockerfile چه کاری انجام می‌دهد؟

    1. پورت Container را مشخص می‌کند
    2. Base Image را تعیین می‌کند
    3. فایل‌ها را کپی می‌کند
    4. Container را اجرا می‌کند

    پاسخ صحیح: گزینهٔ ۲ — FROM تصویر پایه‌ای را مشخص می‌کند که Image جدید روی آن ساخته می‌شود.

  2. دستور FROM معمولاً در کدام قسمت Dockerfile قرار می‌گیرد؟

    1. در ابتدای هر مرحلهٔ Build
    2. فقط در انتهای فایل
    3. بعد از CMD
    4. محل آن اهمیتی ندارد

    پاسخ صحیح: گزینهٔ ۱ — هر Build Stage با یک دستور FROM آغاز می‌شود.

  3. در FROM mcr.microsoft.com/dotnet/sdk:9.0 مقدار 9.0 چیست؟

    1. نام Container
    2. شمارهٔ پورت
    3. Tag مربوط به Base Image
    4. شناسهٔ Build

    پاسخ صحیح: گزینهٔ ۳ — مقدار بعد از دونقطه، Tag ایمیج پایه است.

  4. دستور WORKDIR چه کاری انجام می‌دهد؟

    1. دایرکتوری کاری دستورهای بعدی را مشخص می‌کند
    2. Image را حذف می‌کند
    3. متغیر محیطی ایجاد می‌کند
    4. پورت را منتشر می‌کند

    پاسخ صحیح: گزینهٔ ۱ — WORKDIR مسیر کاری دستورهایی مانند RUN، COPY و CMD را تعیین می‌کند.

  5. اگر مسیر تعیین‌شده با WORKDIR وجود نداشته باشد چه اتفاقی می‌افتد؟

    1. Build همیشه متوقف می‌شود
    2. Docker مسیر را به‌صورت خودکار ایجاد می‌کند
    3. دستور نادیده گرفته می‌شود
    4. Container فوراً اجرا می‌شود

    پاسخ صحیح: گزینهٔ ۲ — Docker مسیر WORKDIR را در صورت نبودن ایجاد می‌کند.

  6. چرا WORKDIR نسبت به RUN cd /app انتخاب بهتری است؟

    1. چون WORKDIR فقط در Windows کار می‌کند
    2. چون RUN cd همیشه Image را حذف می‌کند
    3. چون WORKDIR برای دستورهای بعدی باقی می‌ماند، اما اثر cd در RUN بعدی حفظ نمی‌شود
    4. هیچ تفاوتی ندارند

    پاسخ صحیح: گزینهٔ ۳ — هر RUN لایه و Shell جداگانه‌ای دارد؛ WORKDIR مسیر را برای دستورهای بعدی حفظ می‌کند.
